A trilingual (English, Dutch, Turkish) single-page portfolio. It is also a working example of how I approach quality: every change runs through type checking, unit and end-to-end tests, accessibility checks and performance budgets before it can reach production.

## Quality gates

Every pull request and every push to `main` runs [`quality.yml`](.github/workflows/quality.yml). Nothing deploys unless all of it passes.

| Gate | What it enforces |
| --- | --- |
| Dependency audit | `npm audit --omit=dev` — no moderate-or-worse advisories in runtime dependencies |
| Type check | `tsc --noEmit` under `strict` |
| Unit tests | 62 Vitest tests, coverage gate 80% lines / 75% branches on logic modules |
| End-to-end | 59 Playwright tests on desktop Chrome and Pixel 7, against the production build with production security headers |
| Accessibility | axe WCAG 2.1 A/AA on every page, light and dark theme |
| Lighthouse budgets | Desktop: performance ≥ 90, accessibility / best practices / SEO = 100, LCP < 2 s, CLS < 0.1, scripts < 460 KB |
| Generated files | The sitemap and GitHub profile README regenerated by the build must match what is committed |

Every end-to-end test also fails on any console error, uncaught exception or Content-Security-Policy violation.

Measured on a local production build, Lighthouse desktop: **97 / 100 / 100 / 100** (LCP 0.9 s, TBT 60 ms). Mobile performance is lower (65–78); see [the roadmap](docs/ROADMAP.md).

## Getting started

Requires **Node.js 22 or newer**.

```bash
npm ci
npm run dev          # http://localhost:3000
```

No environment variables are needed. The contact form posts to Web3Forms with a public access key, and analytics is cookieless Plausible.

## Scripts

| Script | Purpose |
| --- | --- |
| `npm run dev` | Development server with HMR |
| `npm run build` | Production build. `prebuild` regenerates the sitemap and profile README; `postbuild` writes `dist/version.json` |
| `npm run preview` | Serve the build, replaying the production security headers from `firebase.json` |
| `npm run typecheck` | Strict TypeScript check |
| `npm test` / `npm run test:coverage` | Unit tests / with coverage gate |
| `npm run test:e2e` | Playwright end-to-end and accessibility suite (builds first if needed) |
| `npm run generate:sitemap` | Regenerate `public/sitemap.xml` |
| `npm run generate:profile-readme` | Regenerate the GitHub profile README in `profile/` |
| `npm run publish:profile-readme` | Push it to [github.com/emredursun](https://github.com/emredursun) |

## How it fits together

```
index.html            Static app shell (first paint before JS), SEO meta, JSON-LD
index.tsx → src/bootstrap.ts   Fonts, icons, Plausible queue, error reporting, service worker
App.tsx               Routing, theme, preloader hand-off, idle-loaded decorative layers
constants.tsx         Portfolio data: services, projects, certifications, tech stack
public/locales/       Copy in en / nl / tr, one JSON file per page
components/           Pages and UI
scripts/              Build-time generators (sitemap, profile README, version stamp)
tests/  e2e/          Vitest unit tests / Playwright end-to-end tests
```

A few decisions worth knowing about:

- **One source of truth for content.** The GitHub profile README is generated from `constants.tsx` and the locale files. The generator refuses to run if the data grows something it cannot express, such as a technology without a badge or a featured project that disappeared. Because `prebuild` runs it, drift breaks the build.
- **Meaningful `lastmod`.** The sitemap timestamp for each route only moves when the files that route renders change. It is tracked by content hash in `scripts/sitemap-state.json`.
- **Strict CSP, tested locally.** `script-src 'self'` with no `'unsafe-inline'`. `vite preview` and the e2e suite apply the same headers as production, so a violation fails a test instead of shipping.
- **Privacy by default.** Plausible is cookieless. Google Maps loads only when the visitor asks for it, and there is no Google Analytics.
- **Errors are reported, never fatal by accident.** A real React error boundary catches render errors. Errors outside the tree are sent to Plausible as a `JS Error` event, with no PII and capped per page, and do not take over the page.

## Deployment and operations

Pushes to `main` deploy to Firebase Hosting through [`deploy.yml`](.github/workflows/deploy.yml) after the quality gates pass. The workflow then smoke-tests the live site against `/version.json`. Pull requests get a preview channel.

How to deploy, check what is live, roll back, and respond to an alert: **[docs/RUNBOOK.md](docs/RUNBOOK.md)**. Release history: **[CHANGELOG.md](CHANGELOG.md)**.
