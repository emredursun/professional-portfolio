A trilingual (English, Dutch, Turkish) single-page portfolio. It is also a working example of how I approach quality: every change runs through type checking, unit and end-to-end tests, accessibility checks and performance budgets before it can reach production.

## Quality gates

Every pull request and every push to `main` runs [`quality.yml`](.github/workflows/quality.yml). Nothing deploys unless all of it passes.

| Gate | What it enforces |
| --- | --- |
| Dependency audit | `npm audit --omit=dev` — no moderate-or-worse advisories in runtime dependencies |
| Type check | `tsc --noEmit` under `strict` |
| Lint | ESLint with typescript-eslint, react-hooks (including the React Compiler rules) and jsx-a11y; any warning fails |
| Formatting | Prettier, checked in CI (`npm run format:check`) |
| Dead code | `knip`: no unused files, exports or dependencies |
| Unit tests | 124 Vitest tests, coverage gate 80% lines / 75% branches on logic modules (currently 85% / 88%) |
| End-to-end | 208 Playwright tests on desktop Chrome and Pixel 7, against the production build with production security headers |
| Accessibility | axe WCAG 2.1 A/AA on every page and the 404 page in light and dark themes, plus the open command palette and project modal |
| Lighthouse budgets | Desktop, median of 5 runs: performance ≥ 90, accessibility / best practices / SEO = 100, TBT ≤ 200 ms, LCP < 2 s, CLS < 0.1, scripts < 460 KB, at most 2 third-party requests. Mobile (Lighthouse's Moto G profile on slow 4G), median of 5 runs: performance ≥ 75 (/projects ≥ 65), accessibility / best practices / SEO = 100, TBT ≤ 300 ms (/projects ≤ 600 ms), LCP < 4 s, CLS < 0.1 |
| Generated files | The sitemap and GitHub profile README regenerated by the build must match what is committed |
| CV | The PDF CV in each language is rendered from the build and checked by the e2e suite |
| Quality report | After every gate passes, `scripts/write-quality.js` turns the run's reports into `dist/quality.json`, which the site's `/quality` page shows. It refuses to write a partial report |

Every end-to-end test also fails on any console error, uncaught exception or Content-Security-Policy violation.

Measured on a local production build, Lighthouse:

| | Performance | Accessibility | Best practices | SEO |
| --- | --- | --- | --- | --- |
| Desktop | 97–98 | 100 | 100 | 100 |
| Mobile | 84 (/projects 75–84) | 100 | 100 | 100 |

The decorative particle field (a 2D canvas) renders only on desktop with a fine pointer; on touch devices it was the entire main-thread blocking cost.

## Getting started

Requires **Node.js 22 or newer**.

```bash
npm ci
npm run dev          # http://localhost:3000
```

No environment variables are needed. The contact form posts to Web3Forms with a public access key. There is no analytics script; search traffic is in Google Search Console.

## Scripts

| Script | Purpose |
| --- | --- |
| `npm run dev` | Development server with HMR |
| `npm run build` | Production build. `prebuild` regenerates the sitemap and profile README; `postbuild` writes `dist/version.json` and the per-route HTML heads |
| `npm run preview` | Serve the build, replaying the production security headers from `firebase.json` |
| `npm run typecheck` | Strict TypeScript check |
| `npm run knip` | Find unused files, exports and dependencies |
| `npm run lint` | ESLint (typescript-eslint, react-hooks, jsx-a11y) |
| `npm run format` / `npm run format:check` | Format with Prettier / check formatting |
| `npm test` / `npm run test:coverage` | Unit tests / with coverage gate |
| `npm run test:e2e` | Playwright end-to-end and accessibility suite (builds and renders the CVs first if needed) |
| `npm run generate:cv` | Render `dist/cv/Emre-Dursun-CV-{en,nl,tr}.pdf` from the build (needs `npx playwright install chromium`) |
| `npm run generate:sitemap` | Regenerate `public/sitemap.xml`: every page and every service and project detail page, in three languages |
| `npm run generate:profile-readme` | Regenerate the GitHub profile README in `profile/` |
| `npm run publish:profile-readme` | Push it to [github.com/emredursun](https://github.com/emredursun) |

## How it fits together

```
index.html            Static app shell (first paint before JS), SEO meta, JSON-LD
index.tsx → src/bootstrap.ts   Fonts, icons, reduced motion, stale-chunk recovery, service worker
App.tsx               Routing, theme, preloader hand-off, idle-loaded decorative layers
constants.tsx         Portfolio data: services, projects, certifications, tech stack
public/locales/       Copy in en / nl / tr, one JSON file per page
components/           Pages and UI
scripts/              Build-time generators (sitemap, profile README, CV PDFs, version stamp)
tests/  e2e/          Vitest unit tests / Playwright end-to-end tests
```

A few decisions worth knowing about:

- **One source of truth for content.** The GitHub profile README is generated from `constants.tsx` and the locale files. The generator refuses to run if the data grows something it cannot express, such as a technology without a badge or a featured project that disappeared. Because `prebuild` runs it, drift breaks the build.
- **Meaningful `lastmod`.** The sitemap timestamp for each route only moves when the files that route renders change. It is tracked by content hash in `scripts/sitemap-state.json`.
- **Real 404s.** `firebase.json` rewrites only the app's routes to `index.html`. Any other path gets `404.html`, a copy of the app shell emitted by the build, with a 404 status, and the app renders a localized, `noindex` "not found" view there. A unit test checks the rewrite patterns against every sitemap URL, and the deploy smoke test checks a live unknown URL returns 404.
- **Every URL has its own head.** After the build, `scripts/prerender-routes.js` writes one HTML file per route (75 URLs in three languages) with that page's title, description, canonical, hreflang, Open Graph tags and JSON-LD, so LinkedIn, WhatsApp and X, which never run JavaScript, preview the right page. The values come from the same locale files and rules as `SEO.tsx`, and an e2e test checks the static head matches what the page renders.
- **One linked entity for search engines.** The JSON-LD is a single `@graph`: Person, portrait `ImageObject`, WebSite and services, all linked by `@id`, plus a `ProfilePage` on the About page. The portrait has a descriptive filename and is listed in the image sitemap.
- **Readable by machines too.** The build writes `/resume.json` in the open [JSON Resume](https://jsonresume.org) format (validated against the official schema in a unit test) and `/llms.txt` per [llmstxt.org](https://llmstxt.org), so ATS tools and AI assistants read the same facts the pages show. Both come from the same data as the pages.
- **The CV is the site.** The downloadable PDF is the site's print layout rendered by headless Chromium after the build, so it cannot drift from the page content.
- **Layout follows the space, not the screen.** Sections use container queries: beside the desktop sidebar a 1100 px window leaves the content about 500 px wide, which viewport breakpoints misjudged.
- **Strict CSP, tested locally.** `script-src 'self'` with no `'unsafe-inline'`. `vite preview` and the e2e suite apply the same headers as production, so a violation fails a test instead of shipping.
- **Privacy by default.** No analytics or tracking scripts, and no cookies. Google Maps loads only when the visitor asks for it. An end-to-end test fails if a page loads anything from a third party.
- **Errors are reported, never fatal by accident.** A real React error boundary catches render errors. Errors outside the tree stay in the browser console and do not take over the page.

## Deployment and operations

Pushes to `main` deploy to Firebase Hosting through [`deploy.yml`](.github/workflows/deploy.yml) after the quality gates pass. The workflow then smoke-tests the live site against `/version.json`. Pull requests run the same quality gates; a Firebase preview channel is deployed only for a PR labelled `preview`.

How to deploy, check what is live, roll back, and respond to an alert: **[docs/RUNBOOK.md](docs/RUNBOOK.md)**. Release history: **[CHANGELOG.md](CHANGELOG.md)**.
